# 種目マスタ設計(ドラフト)

状態: **実装済み**(Web・モバイル)。以下は設計と、確定した判断。

## 1. 決定済みの要件(開発者の指定)

- 部位は 6 つ: 肩 / 胸 / 腕 / 腹筋 / 背筋 / 脚
- 1 種目につき部位は 1 つ
- 種目は自分で追加できる。デフォルトの種目も用意する
- 既存データ(自由入力の種目名)もマスタに取り込む

## 2. 設計案

### 2.1 部位(固定)

- コード内の定数として持つ(`shared/` に配置)。DB には保存しない。
- ID は英字の固定値にする(例: `shoulder` / `chest` / `arm` / `abs` / `back` / `leg`)。表示名は日本語。
- 理由: 6 つに決まっていて、ユーザーが増減させない。DB に置くと同期・移行が増えるだけ。

### 2.2 種目マスタ

| 項目 | 内容 |
| --- | --- |
| 型 | `ExerciseMaster { id, name, part, isDefault }` |
| デフォルト種目 | **コード内の一覧**として持つ。DB には保存しない。ID は固定(例: `default:bench-press`) |
| ユーザー追加の種目 | DB の `documents` に、新しい collection `exercises` として保存(同期される) |
| 画面で使う一覧 | デフォルト + ユーザー追加 を合成したもの |

デフォルトをコードに持つ理由(推測を含む):
- 各端末・各ユーザーへ初期データを書き込む処理が不要で、重複・同期の問題が起きない。
- デメリット: デフォルトの内容を変えると全員に反映される。デフォルトは削除・編集できない(非表示にしたければ別途検討)。

代替案: 初回起動時にデフォルトを各ユーザーの DB に書き込む。→ 編集・削除は自由になるが、複数端末で二重に作らない仕組みが必要になり、複雑。

### 2.3 記録との紐づけ

- `Exercise`(ワークアウト内の種目)に `exerciseId` を追加し、マスタを ID で参照する。
- 既存の `name` は、マスタが見つからないときの**予備として残す**(古い記録を壊さないため)。
- ユーザー追加の種目は、記録で使用中なら削除できないようにする(要確認)。

### 2.4 画面(記録画面)

- 種目名の自由入力をやめ、**部位で絞って種目を選ぶ**形にする。
- 一覧にない種目は、その場で「新しい種目を追加」できる(部位を 1 つ選ぶ)。

### 2.5 既存データの取り込み

- 初回起動時に 1 回、記録内の種目名(前後の空白を除いた文字列)を集めて処理する。
  1. デフォルトの種目名と一致 → その ID に紐づける
  2. 一致しない → ユーザー追加の種目として登録し、紐づける
- 登録する種目の ID は、**名前から決まる固定値**にする(例: `custom:<名前>`)。
  - 理由: 複数の端末が別々に取り込みを実行しても、同じ ID になり、重複しない。
- 既存データには部位の情報がないため、**部位は「未分類」にする**(要確認)。後から画面で部位を割り当てる。

### 2.6 DB への影響

- `documents.collection` の CHECK 制約に `'exercises'` を追加する必要がある(`0003` マイグレーション)。RLS のポリシーは変更不要。
- 同期処理(`shared/sync.ts`)に `exercises` を追加する。

## 3. 確定した判断(開発者の回答)

1. 既存データは **「未分類」** の部位で取り込む。あとから種目画面で部位を割り当てる。
2. **計画の種目も選択式**に揃える(記録と同じ部品を使用)。
3. 記録・計画で使われている種目は **削除できない**。
4. デフォルト種目は下の叩き台のまま(開発者から修正指示なし。追加・変更はコードの `shared/exercises.ts`)。

## 4. 実装メモ

- 部位・デフォルト種目・取り込み処理: `shared/exercises.ts`(取り込みは `linkExercises`。`useAppData` が同期後に自動実行)
- Web: `components/ExercisePicker.tsx`(選択部品)、`components/ExercisesView.tsx`(マスタ管理)
- モバイル: `mobile/src/ExercisePicker.tsx`、`mobile/src/screens/ExercisesScreen.tsx`
- DB: `supabase/migrations/0003_add_exercises.sql`(**0002 の後に、アプリを使う前に実行する**。未実行だと `exercises` を送った同期が失敗し、記録の同期も止まる)
- 名前が同じ種目は追加できず、既存の種目が選ばれる(大文字小文字・前後の空白は無視)。
- 種目名を変更すると、画面にはマスタの新しい名前が表示される。記録内に保存済みの `name` は予備(古い名前のまま)で、進捗の集計は今後 `exerciseId` を基準にする。
