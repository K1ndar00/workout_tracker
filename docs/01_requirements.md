# 要件定義

既存実装から逆算した内容です。「実装済み」は事実、「将来」「対象外」は推測を含むため、開発者が見直してください。

## 1. 機能要件

### MVP(実装済み・コードで確認)

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-01 | ワークアウト記録 | タイトル・日付・絵文字・メモ。種目を追加し、セットごとに回数・重量(kg/lbs)・完了を記録。作成・編集・削除 |
| F-02 | トレーニング計画 | プラン名・説明・週の頻度・Day ごとの種目(セット数・回数・重量)。作成・編集・削除。有効/無効の切り替え(`isActive`) |
| F-03 | 進捗表示 | 週別トレーニング回数(過去8週)、今週・今月の回数、種目数、種目別最大重量(上位8)(**今後、部位別・種目別に特化する予定**) |
| F-08 | 種目マスタ | 部位 6 種(肩・胸・腕・腹筋・背筋・脚)+未分類。初期種目とユーザー追加種目。記録・計画では選択式。使用中の種目は削除不可。既存の自由入力は未分類で取り込み |
| F-04 | アカウント | メール+パスワードでの登録・ログイン・ログアウト |
| F-05 | 同期 | 端末間の自動同期(変更の送信、他端末の変更の受信、アプリ復帰時の更新) |
| F-06 | オフライン動作 | 端末にキャッシュを持ち、オフラインでも閲覧・編集できる |
| F-07 | ローカルモード | Supabase 未設定時は、アカウントなしでその端末のみに保存 |

### 削除済み

- 栄養管理(食事記録・栄養目標)。2026-11 に削除。

### 将来の追加候補(推測。コードに実装なし)

- 部位別・種目別の進捗(種目マスタは実装済みで、集計への反映が次)
- Python による分析用スクリプト(まずはアプリ本体と切り離して学習用に)
- 日付をローカルタイムゾーン基準にする(既知の制限の解消)
- 競合時の項目単位マージ
- 計画からワークアウトを自動生成する
- データのエクスポート・バックアップ
- 体重・体組成の記録
- ストア配布(EAS Build)

### 開発対象外(現時点・推測)

- 他ユーザーとの共有・ソーシャル機能
- 食品データベースの自動検索
- 専用バックエンド API

## 2. 非機能要件

| 項目 | 内容 | 根拠 |
| --- | --- | --- |
| 可用性 | オフラインでも使える | F-06 |
| データ分離 | ユーザーは自分のデータのみ読み書きできる | Row Level Security |
| 整合性 | 端末間で最終的に同じ状態になる | 3 点比較による同期 |
| 対応環境 | モダンブラウザ、iOS / Android(Expo) | `mobile/app.json` |
| 使いやすさ | スマホ幅でも使えるレスポンシブ UI | コミット "Add mobile responsiveness" |
| コスト | 無料枠の範囲で運用する | 要確認(個人開発の方針より) |
| 性能 | 同期は毎回全ドキュメントを取得する。個人利用の量では問題ない想定 | 推測・未計測 |

## 3. 制約条件

- 日付は UTC 基準で、日本時間の 0〜9 時台は「前日」になることがある。
- 同じ項目を複数端末で同時にオフライン編集すると、後から同期した側が残る。
- データは `documents` テーブル1枚の JSON。SQL での集計には向かない。
- 自動テストは未整備。
