# 要件定義

## 1. 機能要件

### 実装済み

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-01 | ワークアウト記録 | タイトル・日付・絵文字・メモ。種目を**選んで**追加し、セットごとに回数・重量(kg/lbs)・完了を記録。作成・編集・削除。自動保存 |
| F-02 | トレーニング計画 | プラン名・説明・週の頻度・Day ごとの種目(セット数・回数・重量)。種目は選択式。有効/無効の切り替え。作成・編集・削除。自動保存 |
| F-03 | 種目マスタ | 部位 6 種(肩・胸・腕・腹筋・背筋・脚)+未分類。初期種目 30 件(変更不可)とユーザー追加種目(名前・部位の変更、削除)。使用中の種目は削除不可(DB が保証) |
| F-04 | 進捗表示 | 今週・今月・累計のワークアウト回数。**部位別**: 過去 8 週の週別ボリューム(重量×回数)・合計・セット数。**種目別**: 部位で絞り込める一覧(最大重量・実施回数・最終日)と、選んだ種目の最大重量の推移(直近 12 回)。完了にしたセットだけを集計し、lbs は kg に換算 |
| F-05 | アカウント | メール+パスワードでの登録・ログイン・ログアウト。ログイン必須 |

### 削除済み

- 栄養管理(食事記録・栄養目標)
- モバイルアプリ(Expo)。スマホはブラウザで利用する
- オフライン編集・端末間同期・ローカルモード(オンライン前提に変更)

### 将来の追加候補(推測)

- 進捗の拡張(推定 1RM、期間の切り替え、部位ごとの種目内訳など)
- Python による分析(`v_set_facts` ビューを読む)
- 計画からワークアウトを自動生成する
- データのエクスポート・バックアップ
- 体重・体組成の記録

### 開発対象外

- 他ユーザーとの共有・ソーシャル機能
- 専用バックエンド API
- オフライン対応

## 2. 非機能要件

| 項目 | 内容 | 根拠 |
| --- | --- | --- |
| データ分離 | ユーザーは自分のデータのみ読み書きできる | Row Level Security |
| 整合性 | ワークアウト・計画は 1 トランザクションで保存。参照されている種目は削除できない | `save_*` 関数・外部キー制約 |
| 使いやすさ | スマホ幅でも使えるレスポンシブ UI | コミット "Add mobile responsiveness" |
| コスト | 無料枠の範囲で運用する | 要確認(個人開発の方針) |

## 3. 制約条件

- オンライン前提。通信できない間は保存できない。
- 同じワークアウトを複数のタブ・端末で同時に編集すると、後から保存した側が残る。
- 入力後 1 秒以内にタブを閉じると、最後の入力が保存されないことがある。
- 進捗の集計は DB のビュー(`0004`)で行う。完了にしたセットのみが対象。
- 自動テストは未整備(DB の SQL はローカル PostgreSQL で手動検証済み)。
